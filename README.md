# 🌿 Biodiversity Finder App

Interactive Streamlit application for **Biodiversity Finder**, an intelligent species search and biodiversity encyclopedia project.

This repository contains the public user interface. It loads pre-generated biodiversity artifacts from Hugging Face and allows users to search, explore, and visualize species information.

## 📌 Project Overview

**Biodiversity Finder App** is the interactive frontend of the Biodiversity Finder project.

The app allows users to search species using:

- scientific names;
- common names;
- multilingual terms;
- taxonomic information;
- descriptive text.

The application does not train the model and does not download raw GBIF data directly.  
Instead, it consumes artifacts generated by the training pipeline.

---

## ✨ Main Features

- Interactive species search.
- Multilingual search support through common names.
- Species encyclopedia cards.
- Species images from GBIF and Wikimedia Commons.
- Filtering by taxonomic class and observation count.
- Model metrics preview.
- Data table with searchable species information.
- Links to training dashboard and Hugging Face artifacts.
- Clean Streamlit interface.
- Modular Python architecture.

---

## 🧠 How the App Works

The app loads the main encyclopedia artifact:

```text
processed/species_encyclopedia.parquet
```

from the Hugging Face dataset:

```text
selenamir/biodiversity-finder-artifacts
```

The search engine compares the user query with an enriched search document built from fields such as:

```text
scientific_name
vernacular_names
kingdom
phylum
taxon_class
taxon_order
family
genus
species
countries
source_queries
profile_text
search_document
```

The app does not hardcode species names.  
Common names are prepared by the training repository using external data sources such as GBIF Species API and Wikidata.

## 🔎 Search Logic

The search logic is located in:

```text
src/search_components/
```

Main modules:

```text
normalizer.py        # text normalization
query_expansion.py   # generic multilingual category expansion
scoring.py           # similarity scoring
filters.py           # dataframe filtering
engine.py            # main search engine
```

The app uses a generic search approach instead of animal-specific rules.

This means the app does not contain rules like:

```text
lion → Panthera leo
jaguar → Panthera onca
leopard → Panthera pardus
```

Those names should come from the enriched encyclopedia data.

---

## 🖼️ Species Images

Image loading is handled in:

```text
src/image_loader.py
src/image_sources/
```

The app searches images using:

1. GBIF occurrence media.
2. Wikimedia Commons fallback.

If GBIF does not provide a usable image, the app tries to find a public image from Wikimedia Commons.

## 🚀 Local Setup

Clone the repository:

```bash
git clone https://github.com/OlenaMyroshnykova/biodiversity-finder-app.git
cd biodiversity-finder-app
```

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/Scripts/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the app:

```bash
streamlit run app.py
```

## 🔄 Relationship with the Training Repository

This repository is responsible for the interface.

The training repository is responsible for:

- downloading GBIF data;
- cleaning records;
- enriching climate data;
- enriching common names;
- training the ML model;
- building the species encyclopedia;
- publishing artifacts to Hugging Face.

The app repository is responsible for:

- loading the generated artifacts;
- rendering the interface;
- searching the encyclopedia;
- displaying species cards;
- showing charts and metrics.

---

## 🧭 Project Conventions

- Variables, functions, and file names are written in English.
- Comments, docstrings, and visible UI texts are written mainly in Spanish.
- The app does not store heavy datasets in GitHub.
- Large artifacts are loaded from Hugging Face.
- The search logic should stay generic.
- Species-specific knowledge should live in the data, not in app code.
